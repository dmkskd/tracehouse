# Guided Tour

:::note[Work in Progress]
TraceHouse is under active development. Feature behavior and interfaces may change between releases.
:::

## Monitoring and Investigation

TraceHouse queries ClickHouse `system.*` tables for query logs, merge activity, resource usage, and part metadata. Its views connect cluster-level metrics to individual query resource usage and table storage layouts to recorded merge history.

## Investigation Workflows

- **Understanding workload in real time**: see which queries, merges, and background tasks are consuming CPU, memory, and I/O right now
- **Investigating specific queries or merges**: trace a slow query's resource footprint, or follow a merge from start to finish
- **Exploring table structure and storage**: inspect parts, columns, compression ratios, and how data is physically organized
- **Historical analysis**: look at past query patterns, merge throughput, and resource trends over time

## Scope and Limitations

TraceHouse focuses on ClickHouse monitoring and investigation:

- **Alerting**: configure notifications separately in Grafana or another alerting system.
- **Cluster management**: server configuration, user administration, and schema management remain outside its scope.
- **Dashboard data**: the built-in views focus on ClickHouse system tables and operational metrics.
