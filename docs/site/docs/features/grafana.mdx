# Grafana Integration

<FeatureVideo src="grafana-1920.mp4" />

TraceHouse can be deployed as a Grafana app plugin. The same static frontend you run standalone is packaged inside Grafana, so you get the full experience - cluster overview, merge tracker, query monitor, database explorer - without leaving your Grafana instance.

## How It Works

In standalone mode, the app connects to ClickHouse directly using `@clickhouse/client-web` over HTTP/HTTPS. In Grafana mode, that connection layer is swapped out: instead of talking to ClickHouse directly, the app sends queries through the [Grafana ClickHouse data source plugin](https://grafana.com/grafana/plugins/grafana-clickhouse-datasource/), which is an external plugin maintained by Grafana.

```
Standalone:   Browser ──HTTP──▶ ClickHouse

Grafana:      Browser ──▶ Grafana backend ──▶ ClickHouse data source plugin ──▶ ClickHouse
```

The app itself is identical - same React UI, same `packages/core` query logic, same attribution models. Only the transport changes.

## Grafana Panel Export

<FeatureVideo src="grafana-export-1920.mp4" />

TraceHouse can export a Query Explorer result as a Grafana panel. The query, chart settings, table styling, drill-downs, links, and panel metadata are derived from the SQL and [Analytics Query Language](analytics-query-language) directives.

This lets you define the panel in TraceHouse first, where editing SQL and chart directives is often faster than configuring the same panel manually in Grafana.

## Linking From Existing Dashboards

<FeatureVideo src="grafana-to-tracehouse-1920.mp4" />

You don't have to replace your existing ClickHouse dashboards to use TraceHouse. A Grafana [data link](https://grafana.com/docs/grafana/latest/panels-visualizations/configure-data-links/) on any panel that shows a query ID can open that query directly in the TraceHouse query monitor.

The link never leaves Grafana. It points to the TraceHouse app plugin installed in the same Grafana instance (a relative `/a/<plugin-id>/...` path), not to a separate TraceHouse deployment. The user stays in the same Grafana session, with the same login and data source permissions, and the query detail is fetched through the same ClickHouse data source the dashboard uses.

The demo stack ships an example: **ClickHouse - Query Analysis [TraceHouse linked]** (`infra/docker/grafana/dashboards/TraceHouse/query-analysis-linked.json`). It is the standard query analysis dashboard with one addition - a field override on the `Query id` column of the "Query overview" table:

```json
{
  "matcher": { "id": "byName", "options": "Query id" },
  "properties": [
    {
      "id": "links",
      "value": [
        {
          "title": "Open in TraceHouse",
          "url": "/a/dmkskd-tracehouse-app/queries?qd_id=${__value.raw}&th_ds=${datasource}",
          "targetBlank": true
        }
      ]
    }
  ]
}
```

Clicking a query ID opens the TraceHouse app page inside Grafana with that query's detail view already loaded. `/a/dmkskd-tracehouse-app/` is Grafana's own route for app plugins, so the URL has no host and resolves against the Grafana instance serving the dashboard. The URL parameters:

- `qd_id` - the query ID to open. `${__value.raw}` is the clicked cell's value.
- `th_ds` - the ClickHouse data source UID. Passing the dashboard's `${datasource}` variable makes TraceHouse use the same data source the dashboard is querying, instead of the last one selected in the app.
- `th_cluster` (optional) - the cluster name to query. If omitted, TraceHouse uses its normal cluster selection.

To add this to your own dashboard, open the table panel, add a field override for the column that holds the query ID, and add a data link with the URL above. Adjust `${datasource}` if your dashboard's data source variable has a different name.

## Differences from Standalone

- **No connection setup** - Users don't enter host, port, or credentials. They pick from the Grafana ClickHouse data sources already configured in their Grafana instance.
- **Permissions handled by Grafana** - Access control, team permissions, and credential management are all delegated to Grafana. If a user has access to a data source, they can use it in TraceHouse.
- **No CORS proxy needed** - Queries are routed through the Grafana backend, so there's no browser-to-ClickHouse CORS issue to solve.
- **Single deployment** - The app is hosted inside Grafana. No separate static site, no extra infrastructure.

## Cluster Selection

When you open TraceHouse in Grafana, you pick which ClickHouse data source to use from a dropdown in the header. If your Grafana instance has multiple ClickHouse data sources configured, you can switch between them at any time.

Once a data source is selected, TraceHouse queries `system.clusters` to detect the cluster topology: how many shards, how many replicas, which clusters are available. If multiple clusters are found, a second dropdown appears next to the data source picker so you can choose which cluster to query. The selection is saved per data source in localStorage, so it persists across sessions.

Under the hood, when a cluster is active, all queries that need cross-node data use `clusterAllReplicas('cluster_name', db.table)` to fan out across replicas. On single-node setups this is skipped automatically.

Grafana admins can also pre-configure a preferred cluster name in the plugin settings (Configuration > Plugins > TraceHouse). If set, it's used as the default instead of auto-detection.
